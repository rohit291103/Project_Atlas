## Last session notes

**The product info page + spec export v0.** The whole change is one finding — *Atlas ingests context and renders a queue over it, and never renders the context itself* — and the parts worth remembering are the ones about what a document owes its reader:

- **A contested claim is not in the settled body at all.** It appears only inside its disagreement, so "not silently resolved" is structural rather than editorial. The alternative — keeping the confirmed side above and saying nothing — *is* silently resolving in favour of whichever side happened to be confirmed first.
- **A disagreement is live while neither side is rejected.** Confirming does not settle a conflict; rejecting the other side does. So both sides render, including an unconfirmed one, each labelled — dropping the unruled side would be the same silent resolution by a different route.
- **Both outputs state what they left out.** A document that silently omits half its material is worse than a short one that says how short it is.
- **The two defects were wording, and only reading real output found them.** The disagreement banner repeated once per pair, because one claim can genuinely contradict two different things; and it read "nobody has ruled yet" when on the live data both sides were confirmed.

**Shipping the export in the same change was the point, not scope creep.** One assembly rendered twice means whatever the page shows is what the file contains. Writing the export later would have meant writing the confirmed-only filter a second time, in a second place, with the first already drifting.

**Previously — slice 3 built, test-first, backend only.** The whole slice is one idea — *there is nowhere to put what a product or a feature is* (finding F2 of 2026-08-19) — and the interesting parts were all about what an append-only log does to an ordinary text field:

- **A rename must not blank a description.** `product_renamed` rebuilt the projected `Product` wholesale, so the moment a second field existed the rename would have silently cleared it. Caught by writing the test before the field. It now supersedes only the name.
- **Blank has to be allowed**, because in a forward-only log refusing it makes a wrong description permanent. Empty and `None` collapse at the projection so no reader special-cases `""`, and the text is trimmed — the line between authored prose and a `SourceRef.excerpt`, which must stay literal.
- **Products raise on an unknown id; feature scopes do not.** A product cannot exist without a `product_created`, so an unknown one is a corrupt log. A *scope* can legitimately have nodes and no `ingestion_run` (the pre-1A′ case), and a replay that raised there would make an append-only workspace unreadable forever over a piece of orientation text. So a feature description resolves at the end of `replay` alongside `product_id` — order-independent, inert if it names a scope no run opened — and the API refuses to write one for an unnamed scope, closing the gap from the wire side instead.

**Applied live the same session.** Migration `b41c9d0e7f38` is on Supabase and the enum check was run **as `atlas_app` rather than the owner**, so it covered the grants and the RLS scope too: both event types wrote, replayed through the projection, and cleared. The four probe events are `actor='cli'` / `actor_kind=automated`, and both live products and all seven feature scopes read `description = None` again afterwards — nothing was left saying anything about the user's own data.

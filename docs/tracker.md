## Engineering

### Done
- **Phase 0 complete** — all four modules (`ingestion/` read-only GitHub connector, `extraction/` Claude Agent SDK agent + validation gate, `storage/` event_log + projection replay, `cli/` `atlas ingest`/`review`) built, tested, reviewed clean. Extraction ran live end-to-end on the 4 golden PRs, exit criterion MET.
- **Phase 1 slice 1A — confirmation loop (backend)** (172 tests green, `src/` clean under ruff + strict mypy; code committed as `caf4075`, provenance follow-up uncommitted):
  - `node_confirmed` / `node_edited` / `node_rejected` replay handlers — supersede a node by rebuilding it through `Node.model_validate`, so a transition passes the same gate a create does; `updated_by`/`updated_at` come from the Event's own `actor`/`timestamp`. Last write wins, so undo is free. A transition naming an unknown node raises rather than being skipped.
  - `event_log.sequence` — Postgres identity column, unique, `(workspace_id, sequence)` index; `load_projection` orders by it instead of wall-clock `timestamp`. Migration `8c41a0b7e2d5` backfills existing rows in the old `(timestamp, id)` order so a pre-existing log replays identically.
  - `Node.confidence_score` is `float | None`, present **exactly** when `created_by = system` (both directions enforced). `atlas review` renders an absent score as `—`.
  - `storage/confirmations.py` — `confirm_node` / `reject_node` / `edit_node` / `add_node` over `append_event`; the shared write path for the future API and the CLI. Confirm/reject/edit take the `Node`, not a bare id, so an action can't name one that doesn't exist.
  - `append_event` now rejects a blank `actor` (every Event is an audit record — `NOT NULL` doesn't catch `""`).
  - Manual add reuses `node_created` with `created_by = user`; **no** `node_added` event type was added (TRD §3.1's enum has none). `add_node` builds the Node from fields rather than accepting one, so extraction output can't be laundered through it and an API body can't choose its own `workspace_id`.
  - `SourceType.human_assertion` — a manual node's provenance is the named human who typed it (`external_id` = actor, `excerpt` = the claim as typed, `url` = `atlas:node/<uuid>`), so `source_refs` keeps `min_length=1` with no exception clause. The excerpt is a snapshot: a later edit changes `content` and leaves it alone.
- **Phase 1 slice 1A′ — feature-scope identity** (192 tests green, `src/` clean under ruff + strict mypy):
  - `IngestionRunPayload` (`feature_scope_id`, `title`, `source_type`, `external_id`, `url`) in `models/schema.py`, validated on write *and* on replay. `external_id` fully qualifies the artifact (`BurntSushi/ripgrep#111`) — a scope is workspace-global, so a bare PR number identifies nothing.
  - `record_extraction` emits `ingestion_run` **first and mandatorily** — writing nodes under a scope nobody can name is the gap this closes, so it isn't declinable.
  - `Projection.feature_scopes` → `FeatureScope(id, title, runs)`; `INGESTION_RUN` left `_NO_OP_EVENTS`. `runs` accumulate (1C's Jira source appends); title is last-write-wins. `for_feature_scope` narrows it; a pre-1A′ scope replays as unnamed rather than crashing. No migration, no new event type, no new table.
  - `extract_from_pull_request` returns `(IngestionRunPayload, ExtractionResult)` — built where the fetched PR lives, so no second fetch and no hand-assembled URL competing with the connector's parsed `html_url`.
  - `atlas ingest` prints the scope name; `atlas review` headers the report with the title + "Assembled from" sources — the CLI mirror of the UI header.
- **Phase 1 slice 1B — confirmation UI** (215 tests green incl. 23 API tests; `src/` clean under ruff + strict mypy; SPA typechecks + builds):
  - **`src/atlas/api/`** — flat `app.py`/`deps.py`/`routes.py` per the thinness rule. Every write endpoint is *authenticate → load projection → call one `storage/confirmations.py` function → return*. No `api/schemas.py`: `Node`/`Edge`/`FeatureScope` serialize as themselves; the only declared models are input bodies + one read envelope.
  - **Auth seam** — `get_principal()` → frozen `Principal(workspace_id, actor)` from a signed httpOnly cookie (`itsdangerous`) behind a shared passphrase. No route reads `workspace_id`/`actor` from a request; the cookie carries the actor only, never the workspace. `ApiSettings` deliberately excludes `GITHUB_TOKEN` — the web-facing process holds no source credential.
  - **`NonBlankStr`** in `models/schema.py` — one definition of "not blank", replacing four hand-rolled copies and reused by the API's request bodies, so whitespace content is a 422 at the wire instead of a 500 from the gate behind it. (Found by a test.)
  - **`frontend/`** — Vite + React + TS, OpenAPI-generated types, no component library, no state library. Focus-model review page (why→what→how sections, unconfirmed-first, reviewed items recede), monospace provenance well + `↗ source`, amber cross-source conflict banner, inline edit, add-composer that never asks for a citation, keyboard `j/k/c/e/x/a/o/u`, dark-canonical tokens with a light remap.
  - Verified end-to-end over real HTTP against a seeded local log: 401s, sign-in, list/detail, confirm→`updated_by` = cookie actor, edit→`edited`, blank edit→422, manual add→`human_assertion` provenance, identity-in-body→422, sign-out→401, dev CORS preflight.
- **Phase 1 slice 1C — Jira, the second source** (`docs/decisions/2026-08-11-jira-second-source-slice-1c.md`):
  - `ingestion/jira.py` — read-only Jira Cloud connector, same shape as `github.py` (GET-only, transient DTOs, `/browse/<KEY>` provenance URLs). **Auth is email + API token, resolving §10 Q4**: the token carries exactly its owner's permissions, so least privilege holds with no scope negotiation.
  - **ADF flattening** (`adf_to_text`) — Jira's rich text is a JSON tree and an excerpt must stay literal, so unknown node types are descended into rather than skipped. Heaviest-tested part of the connector; a quietly-truncated excerpt is fabricated provenance.
  - **The GitHub system prompt is frozen by a golden test** — the shared prompt template renders it byte-identically to the version Phase 0's evals validated, so adding a source can't silently invalidate that evidence.
  - **Cross-source `conflicts_with`** — a run into an existing scope is handed the claims other sources already produced and may point an edge at one of *those* ids. The gate got stricter: an id not offered to that run is rejected, because a fabricated relationship is indistinguishable from a real one.
  - **A scope keeps the title of the run that opened it** — the deliberate exception to last-write-wins, resolving what 1A′ deferred: a Jira ticket must not rename a feature a GitHub PR named, mid-review.
  - `atlas ingest-jira --issue/--epic/--label [--feature-scope]`; the UI's conflict banner names the other side's source.
- **Phase 1 slice 1D — scope, RBAC, audit** (`docs/decisions/2026-08-11-scope-rbac-audit-slice-1d.md`):
  - **Scoped ingestion** by issue/epic/label with a hard `--limit` ceiling (TRD §4.2) — deliberate pulls, never a crawl.
  - **`workspace` + `workspace_member` tables, three roles.** The `DEFAULT_WORKSPACE_ID` sentinel became a **real row keeping its own id**, so no append-only event was rewritten. Membership is read per request (revocation takes effect immediately, not at cookie expiry); `workspace_member.actor` is the same string every Event carries, so authorization and audit key on one identity. Viewers read but cannot rule; the API 401s an unknown session and 403s a known non-member.
  - **RLS migration `b7c2f1a45d90`** — policy on `event_log` reading `current_setting('atlas.workspace_id')`, `FORCE`d so it binds the owner role too. **Written, not applied, and not exercised by the suite** (SQLite has no RLS); only the scoping seam is tested.
  - **Tool-call audit logging closed** — the permission gate records every decision, **including denials**, onto the `ingestion_run` event as an optional field that replays cleanly over older events. `emit_extraction` is excluded (it is the run's result, not an access).

## Last session notes

**Built slices 1C and 1D — the second source, and scope/RBAC/audit.** 271 tests green (26 new), `src/` clean under ruff + strict mypy, SPA typechecks and builds. Verified over real HTTP against a seeded local log: a non-member is refused at sign-in (403), an editor confirms and the event carries their name, a viewer reads the same scope but is refused every write, and one feature scope shows "assembled from" GitHub **and** Jira with a cross-source `conflicts_with` between them.

**The interesting decisions.** (1) **Cross-source conflict needed the gate to change**, and the reason is easy to miss: each extraction run only ever sees its own artifact, so a PR saying "must stream" and a ticket saying "we agreed to buffer" cannot conflict as far as either run knows. A run into an existing scope is now handed the claims other sources produced and may point an edge at one of their ids — but **only at an id it was actually offered**, so the gate got stricter, not looser. A fabricated relationship is shaped exactly like a real one. (2) **The GitHub prompt is frozen by a golden test.** Adding a source that silently re-words the prompt would leave Phase 0's eval evidence describing a system that no longer exists; now any edit to the shared template fails loudly and forces a re-run. (3) **A scope keeps the title of the run that opened it** — reversing what 1A′ chose, exactly as 1A′ flagged it would need to at 1C: last-write-wins would rename a feature under a reviewer mid-review. (4) **The nil workspace sentinel became a real row keeping its own id**, so the "reassign every nil-workspace event" the 2026-07-21 decision anticipated never had to happen — rewriting an append-only log to tidy an identifier is a bad trade. (5) **Denied tool calls are recorded**, and they are the valuable half of the audit trail: they are the record of the read-only boundary actually holding.

**Three things are built but unverified, and this is the honest state of Phase 1:**
- **Jira extraction has no eval evidence.** New prompt, new tools, new cross-source instruction — a new LLM code path, which CLAUDE.md says needs `writing-evals` + `extraction-quality-review` before it counts as done. Every Jira test replays recorded fixtures; **it has never run against a real Jira site.**
- **RLS is written, not run.** The policy is DDL in migration `b7c2f1a45d90`; the suite is SQLite, which has neither `set_config` nor RLS, so only the scoping seam is tested. **The migration has not been applied to Supabase** — that is the user's call. Until then, workspace isolation rests on the application-level filter alone (where it already rested — no regression, but not yet the improvement).
- **The UI still has never rendered in a browser.** No browser tooling in either session.

**And the thing that actually matters:** the Phase 1 exit criterion is a *measurement* — a PM outside the build team, unassisted, under 20 minutes — and nobody has taken it. Everything above is preparation for that. There is also an unresolved reading of the criterion worth settling before the demo: it says "connect two sources", ingestion is still CLI-triggered, and there is deliberately no ingest endpoint (that exclusion is what keeps the API queue-free).

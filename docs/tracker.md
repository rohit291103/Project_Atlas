## Last session notes

**The session began as a sanity check on the founding pitch and ended by changing the roadmap and finding three defects.** The engineering half of the original CEO/CTO/PM critique turned out to have been followed unusually faithfully — draft-not-fact, event log, read-only, provenance, security-first are all enforced in code, not merely quoted. The sequencing half had not: the critique named the atomic unit of value as ingest → spec → provenance → approve → hand to the agent, v1 scheduled it for Phase 2, and five real weeks in `find src -iname "*spec*"` returned nothing. **PRD §6's core metric — agent output quality with the spec vs. without — had been unmeasurable for the entire project.** roadmap-v2 pulls export forward, splits the third source out, and replaces a self-reported exit criterion with a blind, pre-registered, N≥5 measurement that runs first against the internal golden set, so the core proof is no longer hostage to recruiting a design partner.

**`Event.actor_kind` closed the hole behind the 2026-08-16 incident** — and one correction is worth recording: `actor_kind` alone does **not** fix it. The browser suite signs in through the real form and holds a real cookie, so the API cannot tell it from a person by inspection and would have written HUMAN. The fix is that a client *declares itself* a machine via `X-Atlas-Automated`, and only that downgrade is claimable, since letting a caller claim HUMAN would hand a bot the one label the guard metric trusts. That fixes attribution, not mutation.

**Then three questions from the user about what a PM would actually experience, all checked against the code and all confirmed.**
- **Nothing updates on its own** — pull-on-demand only, by design. But **re-running the same target duplicates every claim**: no dedup exists in `pipeline.py`, node ids are minted per run, and the projection says outright that a second run "adds to" the scope. A reviewer could confirm one copy and reject the other. Philosophy §5 declares idempotent ingestion binding from Phase 1 onward and nothing enforces it — the most serious of the three, because §5 is in the non-negotiable list.
- **There is no field to hold product context.** `Product` has a name; `FeatureScope` has a title it inherited from whatever artifact opened it. So this is not a missing screen. It also names the cost of the 2026-08-16 Overview change, which replaced a summary with counts: right for the returning reviewer, and it removed the only orientation a first-time visitor had. Amended, not reversed — orientation returns *above* the counts.
- **ripgrep is a validation fixture being used as demo data**, and those are different jobs. Staged as-is, the PM measurement would have tested whether a non-engineer can follow a Rust CLI tool's PR history. **Replacing it is now a prerequisite of the Phase 1 exit criterion, not a follow-up to it.**

**Two things need the user before their slices can be built:** whether a feature's description is PM-authored or extracted (if extracted it is a claim and must carry provenance and start unconfirmed), and whether the re-run guard warns or hard-blocks.

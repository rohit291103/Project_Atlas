## Snapshot

Project Atlas has a scaffolded Phase 0 repo with a full industry-standard dev-tooling layer around it, and a docs tree organized to scale past Phase 0. The PRD, TRD, Roadmap, and Phase 0 Architecture are written, settled, and filed under `docs/prd/` and `docs/architecture/`; `docs/decisions/`, `docs/handoff/`, `docs/research/`, and `docs/ux/` exist as the permanent-record subfolders going forward. The `storage/` module is now complete for Phase 0: Supabase Postgres provisioned, the append-only `event_log` table implemented per TRD §3.1 (migration applied to the live instance), and `storage/projections.py` replays that log back into materialized Node/Edge state (TRD §3.2) — a pure `replay()` reducer plus a DB-backed `load_projection(workspace_id, feature_scope_id=?)`. `models/schema.py` implements the full Pydantic v2 data model (SourceRef/Node/Edge/Event, mirroring TRD §3.1 exactly) with the provenance gate enforced structurally — a Node without a SourceRef is impossible to construct, on both the write and the read (replay) path. `EventType` lives in the schema as the single source of truth; `storage/tables.py` imports it. Ingestion is real: `ingestion/github.py` is a read-only GitHub REST connector (`GitHubClient` — GET-only, Bearer auth, PR/issue/commit fetch with paginated comments + a `search_issues` primitive). All four core modules now have working code: `extraction/` implements the Claude Agent SDK agent — a pure `build_result` validation gate (raw agent payload → schema-validated Node/Edge, the one-rule-no-exceptions gate), read-only SDK tools wrapping the connector, the extraction prompt, and a `run_extraction` orchestrator that retries once then errors. The LLM call sits behind an injectable seam so the whole validate/retry flow is tested with no API key. `cli.py` now wires the pipeline end-to-end: `atlas ingest --repo owner/name --pr N` runs GitHub→extraction→`append_event` (and prints a fresh `feature_scope_id`), and `atlas review --feature-scope <id>` replays the log via `load_projection` into a Rich console report of the draft nodes (grouped by type, with confidence + status + literal source excerpt). What remains before Phase 0's exit criteria is all gated on an ANTHROPIC key + a chosen validation OSS repo: pick the repo + 3–5 PRs, run `atlas ingest` live end-to-end, and grade output through the `writing-evals` / `extraction-quality-review` loop against the exit criteria.

### Done
- Repo scaffolded per `docs/architecture/Phase0_Architecture.md` §5: `pyproject.toml` (Python 3.12, `uv`, deps installed, `uv.lock` committed), full `src/atlas/` package layout, and `tests/` + `tests/evals/` directories. `config.py` reads `ANTHROPIC_API_KEY` / `GITHUB_TOKEN` / `SUPABASE_DB_URL` from env; `cli.py` has a working Typer `atlas` entrypoint with `ingest`/`review` stub commands (`NotImplementedError`). `.env.example` added. Note: nothing in the codebase loads `.env` into the process automatically (`uv run` does not do this) — running the CLI for real will need that wired up (`python-dotenv` is already an indirect dependency).
- Dev-tooling layer added: ruff (lint + format, `select = [E, F, I, UP, B, C4, SIM]`) and mypy (`strict = true`) configured in `pyproject.toml`; `pytest` config section added; `.pre-commit-config.yaml` (ruff, mypy, basic hygiene hooks) installed into `.git/hooks/pre-commit`; `.github/workflows/ci.yml` runs lint + format-check + mypy + pytest on every push/PR to `main`; `.editorconfig` added; `.python-version` pinned to 3.12. Verified end-to-end: `ruff check`, `ruff format --check`, `mypy src`, `pytest`, and `atlas --help` all pass clean.
- Supabase project provisioned (free tier, hosted Postgres); `SUPABASE_DB_URL` set in local `.env` (gitignored, never committed).
- `storage/db.py`: SQLAlchemy 2.0 engine/session (`get_engine`, `get_sessionmaker`, `session_scope`), `Base` declarative base. `normalize_database_url()` rewrites Supabase's bare `postgresql://` connection strings to `postgresql+psycopg://` (psycopg v3 is the installed driver, not psycopg2 — without the rewrite, connecting fails with `ModuleNotFoundError`). `pool_pre_ping=True` guards against stale hosted-Postgres connections.
- `storage/tables.py`: the append-only `event_log` table (TRD §3.1 Event shape exactly — `id`, `event_type`, `payload` JSON/JSONB, `actor`, `timestamp`, `workspace_id`) plus `append_event()` as the sole write path. No update/delete helper exists anywhere in the module (enforced by convention + a test asserting neither symbol exists). `EventType` enum column uses `values_callable` so Postgres stores the lowercase TRD values, not Python's uppercase member names — a real bug caught by testing against live Postgres (SQLite has no native enum constraint and silently accepted the mismatch).
- Alembic wired up and run for real: `alembic.ini` (connection string deliberately left blank — `migrations/env.py` reads `SUPABASE_DB_URL` from the environment at runtime, never committed), initial migration `create_event_log` applied to the live Supabase instance via `alembic upgrade head` and verified by inspecting the resulting table + a real write/read/delete round-trip. `id` has a DB-level default (`gen_random_uuid()`) in addition to the ORM-level one, so inserts that bypass the ORM still get a valid id.
- `tests/test_storage.py`: 9 tests covering table shape, `append_event` write/read round-trip, transactional rollback on error, the enum value-vs-name storage regression, and `normalize_database_url`'s URL-rewrite behavior (bare scheme, explicit driver, non-Postgres schemes) — all against in-memory SQLite, no live DB required in CI.
- Storage reviewed via `security-review` (no findings — no user input reaches SQL, no secret logged or committed, DB URL is env-only) and `backend-reviewer` (no blocking issues; see Next up for the open `workspace_id` design question it raised).
- `models/schema.py`: full Pydantic v2 core data model (TRD §3.1 mirror, field-for-field) — `SourceRef`, `Node`, `Edge`, `Event` on a shared `AtlasModel` base with `extra="forbid"` (rejects hallucinated extraction fields), plus all six enums (`SourceType`, `NodeType`, `NodeStatus`, `CreatedBy`, `RelationType`, `EventType`). The non-negotiable provenance rule is structural: `Node.source_refs` requires ≥1 entry and `SourceRef.excerpt`/`url` reject blank/whitespace, so a Node without literal provenance cannot be constructed. `confidence_score` bounded [0.0, 1.0] on Node+Edge; `status` defaults to `unconfirmed`; excerpts preserved verbatim (never stripped) for provenance verification; Edge rejects self-references. Built test-first per `tdd`; `tests/test_schema.py` has 37 tests weighted toward failure cases (empty provenance, out-of-range confidence, unknown enums, `extra="forbid"` on every entity, JSON round-trip for event-payload storage). Reviewed via `backend-reviewer` — clean, confirmed faithful TRD mirror and sound provenance gate.
- `EventType` unified: moved from `storage/tables.py` into `models/schema.py` (schema is the single source of truth); `storage/tables.py` now imports it (storage→models dependency direction). Kills the duplicate-enum drift risk. `alembic check` confirms zero DB schema drift from the change; all storage tests still green.
- `workspace_id` source decided (`docs/decisions/2026-07-21-phase0-default-workspace-id.md`): `config.DEFAULT_WORKSPACE_ID = uuid.UUID(int=0)` (nil sentinel), stamped by application code, with the schema field kept *required* (not defaulted) so the single-workspace assumption stays visible at call sites and disappears cleanly in Phase 4. `tests/test_config.py` guards its stability. Unblocks projections/ingestion/extraction.
- `storage/projections.py`: event-log replay → materialized Node/Edge state (TRD §3.2), built test-first per `tdd` (`docs/decisions/2026-07-22-projections-event-replay.md`). Pure `replay(events) -> Projection` fold (structural `Protocol` over both `EventLog` rows and `Event` models) + thin `load_projection(session, *, workspace_id, feature_scope_id=None)`. Re-validates every `node_created`/`edge_created` payload through the Pydantic gate on read (provenance holds on the read path too); skips audit-only `ingestion_run`/`spec_exported`; raises `NotImplementedError` on the Phase 1 `node_confirmed/edited/rejected` events rather than silently mishandling them; exhaustive `else` guards a new EventType with no handler. `Projection.for_feature_scope()` filters nodes by scope and drops edges with an endpoint outside it. `tests/test_projections.py`: 16 tests (pure replay, Phase 1 fail-loud, read-path provenance revalidation, scope filtering, DB round-trip incl. workspace + feature-scope filtering).
- `storage/tables.py` UUID columns made dialect-portable — `PG_UUID(as_uuid=True).with_variant(Uuid(as_uuid=True), "sqlite")` (mirrors the existing JSON/JSONB variant). Fixes a real SQLite-only defect surfaced by the projection tests: the nil `DEFAULT_WORKSPACE_ID` (`"000…0"`, all digits) got NUMERIC affinity under the bare `UUID` type name, coercing to integer `0` and crashing on read. Postgres DDL byte-identical (verified offline via `CreateTable` compile) — zero migration drift; only SQLite emission changes to `CHAR(32)`.
- `ingestion/github.py`: read-only GitHub REST connector (`docs/decisions/2026-07-22-github-ingestion-connector.md`). `GitHubClient` (httpx-backed, Bearer auth, `X-GitHub-Api-Version` pinned) exposes `fetch_pull_request` (title/body/state + full paginated conversation comments), `fetch_issue`, `fetch_commit`. Owns *all* GitHub HTTP + JSON parsing so the later `extraction/tools.py` agent tools wrap it thinly and the read-only guarantee lives in one place. Returns transient frozen-dataclass DTOs (`PullRequest`/`Issue`/`Commit`/`IssueComment`, TRD §4.2 — not domain Nodes), each carrying the provenance handles a SourceRef needs (number/sha, html url, literal text). `GitHubError` surfaces failures and flags rate-limit (403/429 + `X-RateLimit-Remaining: 0`) rather than auto-retrying. `tests/test_github.py`: 10 tests via `httpx.MockTransport` replay of `tests/fixtures/github/*.json` (parsing incl. nested commit author/message, `extra`-field tolerance, comment pagination, 404 + rate-limit errors, a **GET-only** read-only assertion, and Bearer/API-version headers). No live API/token/network in tests. Inline security cross-check clean (GET-only test-enforced, token header-only never logged, no persistence).
- `ingestion/github.py` `search_issues`: read-only `GET /search/issues` primitive added when the extraction `search_repo` tool needed it (reuses the issue parser; scoped per-repo by the tool). Still deferred in the connector (not built ahead): incremental sync / `last_synced_at` (Phase 1), auto-backoff/retry.
- `extraction/` (Claude Agent SDK) — all three files + the validation gate (`docs/decisions/2026-07-23-extraction-agent.md`). `agent.build_result` is the pure schema-validation gate: raw agent payload → domain Node/Edge or raise (rejects missing/blank provenance, unknown enum, hallucinated field, duplicate node ref, dangling/self edge), assigning UUIDs, wiring edges via the agent's local `ref` ids, mapping low/medium/high confidence to 0.3/0.6/0.9, stamping workspace/feature scope. `run_extraction` orchestrates via an injectable `AgentCall` seam (LLM call isolated) — validate, retry once with the error fed back, then `ExtractionError`. `tools.py`: read-only SDK tools (`fetch_linked_issue`/`fetch_commit`/`search_repo` wrapping `GitHubClient`, `emit_extraction` as the forced output tool). `prompts.py`: extraction system prompt + seed-prompt builder. Agent locked down by a single `can_use_tool` gate (the authority): allows only the 4 atlas tools, always permits `emit_extraction`, and **counts fetch/search calls to enforce the ~8-call cost cap** (Phase0 §2) — deeper than `max_turns`, which can't cap parallel calls in one turn. Built-ins hard-denied via `disallowed_tools`, `setting_sources=[]`, no `allowed_tools`/`bypassPermissions`. Tool handlers surface httpx transport errors (not just `GitHubError`) as error results and offload the blocking sync connector via `asyncio.to_thread` so they don't stall the SDK loop. `tests/test_extraction.py`: 24 tests (confidence map, gate happy + failure cases, transcript parsing, retry-once flow via a fake agent, tool formatting + transport-error via `httpx.MockTransport`, permission-gate cap/allow/deny) — **LLM never called, no key needed**. Introspected the installed `claude-agent-sdk` (0.2.116) for its real API rather than guessing.
- `cli.py` wired end-to-end (`atlas ingest`/`review`), connecting all four modules. `ingest --repo owner/name --pr N`: `load_dotenv()` → `Settings.from_env()` → `GitHubClient` → `extract_from_pull_request(...)` (fresh `uuid4` feature_scope_id per run) → `record_extraction` writes `node_created`/`edge_created` events via `append_event` → prints the feature_scope_id. `review --feature-scope <id>`: `load_projection(...)` → `render_projection` Rich report (nodes grouped by type, showing content/confidence/status/`url`+verbatim excerpt, plus edges). `review` needs only `SUPABASE_DB_URL` (not the ANTHROPIC key), so it works before keys land. The report gives each node a short-id column and references those same short ids in the Edges table so a reviewer can map an edge to its endpoints; `ingest` catches `GitHubError`/`ExtractionError` and prints a clean message instead of a traceback. Reusable pieces (`_parse_repo`, `_short_id`, `record_extraction`, `render_projection`) factored out of the command bodies; `tests/test_cli.py`: 8 tests incl. a full persist→replay→render round trip through in-memory SQLite (no LLM, no live DB) and an edge-mappability assertion. `atlas --help` verified. Command bodies (live GitHub/agent/Postgres) intentionally not unit-tested (lighter-touch CLI wiring per `tdd`).
- `feature_scope_id` source resolved: each `atlas ingest` run mints a fresh `uuid4`, surfaced to the user, and consumed by `atlas review --feature-scope <id>`. No sentinel needed (unlike workspace_id).
- Deliberately not added yet (would be premature at this stage): LICENSE (commercial product, undecided), Makefile, Dependabot/renovate, issue/PR templates, CODEOWNERS, Docker/devcontainer (contradicts the no-local-container decision already made for Supabase).

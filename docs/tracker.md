## Last session notes

**The session started as a sanity check on the original pitch and ended by changing the roadmap.** Comparing the founding CEO/CTO/PM critique against the repo showed the *engineering* half of that advice had been followed unusually faithfully — draft-not-fact, event log, read-only, provenance, security-first are all enforced in code, not just quoted in a doc. The *sequencing* half had not. The critique named the atomic unit of value as ingest → spec → provenance → approve → hand to the coding agent; v1 scheduled that for Phase 2, and five real weeks in, `find src -iname "*spec*"` returned nothing. The loop ends at "a human confirmed some claims", so **PRD §6's core metric — agent output quality with the spec vs. without — has been unmeasurable for the whole project.**

**Two further defects in v1 were worse than the sequencing.** Phase 2 bundled spec export with a third source, which retires a different risk and only delays the first. And its exit criterion — *"a design-partner team reports whether output quality improved"* — was self-reported, n=1, unblinded, with no rubric, to validate the single claim the product rests on. That is a **lower** bar than `tests/evals/` already applies to extraction. v2 requires blind grading, N≥5, and a rubric pre-registered before any result is seen — and the first signal runs **internally** against the `ripgrep` golden set, so the core proof is no longer hostage to recruiting.

**The YC RFS question was answered and deliberately declined.** "Cursor for PMs" is discovery-side (interviews in, *what to build next* out); Atlas is delivery-side. The adjacency is cheaper than it looks — `NodeType.EVIDENCE` and `PROBLEM` already exist and `prompts.py` extracts evidence today, so it is a connector and a view rather than a rewrite — but chasing it would trade a proven bet for an unproven one. Recorded in the decision doc so it is not rediscovered as a surprise.

**Then the actor hole got closed, because it turned out to be a dependency and not just a defect.** Every v2 metric reads confirmation data and Phase 2's export reads *confirmed* nodes, so building the export on an unverified confirmation record would embed the "silent bad context" failure into the artifact the product exists to produce. `Event.actor_kind` is required with **no default** — a default would silently mislabel whichever call site forgot, which is the exact failure it exists to prevent. mypy then named all 9 production call sites and the suite named 85 more, which was the audit.

**One thing `actor_kind` alone does *not* fix, and it is worth being clear about.** The browser suite signs in through the real form and holds a real cookie, so the API cannot tell it from a person by inspection. The fix is that a client may **declare itself** a machine via `X-Atlas-Automated` (Playwright sets it for the whole suite), and only that direction is claimable — letting a caller claim HUMAN would hand a bot the one label the guard metric trusts. That fixes attribution. It does **not** stop the suite mutating a shared log, and a dedicated workspace is still the real fix and still unbuilt.

**Not done, and blocking:** migration `f9b41d7e3a52` has not been applied to the live database. The offline SQL renders correctly, but applying it is a live schema change on real data. **The API cannot write any event until it runs**, since the column is NOT NULL.

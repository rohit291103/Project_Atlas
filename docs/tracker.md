## Last session notes

**Ran the `codebase-design` gate on the `api/` + frontend boundary — no code written.** The gate passed the §5 decomposition, but the useful output was the four things §5 didn't say. (1) **`api/` is justified as a *transport boundary*, not an abstraction** — it formally fails the skill's "is there a second caller?" test and passes anyway, because its one caller is a browser across a network, which is what makes the boundary load-bearing. (2) The real risk isn't module count, it's `api/` growing a service layer that reimplements `storage/confirmations.py` — so the gate's actual deliverable is a **thinness rule**: HTTP/auth/serialization only, no domain logic, every write endpoint is *authenticate → load projection → call one `storage/` function → return*; no `api/schemas.py` (a second wire-level model layer could drift from the validation gate), no repository pattern, flat three-file layout. (3) **The finding that mattered most is a `storage/` gap, not an API question:** `atlas ingest` mints a bare `uuid4()` scope and **never emits an `ingestion_run` event** — the enum member exists, `projections.py` skips it, nothing writes it — so the log knows ten nodes share a UUID and nothing about what that UUID *is*. The UX spec's left rail and page header have no data source, and "PM navigates by raw UUID" doesn't clear the 20-minute bar. Both shortcuts were rejected (UUIDs-in-the-URL defers the same work into the middle of 1B; a name map in `api/` puts scope identity outside the event log), so it's sequenced as **slice 1A′** and is the next code to write. (4) **§10 Q2 (app auth) was never a scaffolding blocker** — separating the *seam* (`get_principal()` → frozen `Principal`, fixed now, survives Phase 4) from the *implementation* (signed session cookie + passphrase; the PM's typed name becomes `actor`) unblocks the build; only shipping waits. Also decided: **no ingest endpoint in 1B**, which is what keeps the API synchronous and removes all task-queue pressure — ingestion stays CLI-triggered, connect-sources is 1C/1D. Frontend: repo-root `frontend/` (not under `src/atlas/` — hatchling packaging), Vite+React+TS, OpenAPI-generated types, no component library, no state library until undo/optimistic updates earn one. Logged `docs/decisions/2026-08-11-api-frontend-module-boundary.md`; `Phase1_Architecture.md` §5 amended to settled, §4.4 added, §10 Q1–Q3 all marked resolved. **Deliberately not done:** any scaffolding of `api/` or `frontend/` — 1A′ comes first.
